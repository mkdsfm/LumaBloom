# Критерии приёмки: прошивка ESP32-C3 Super Mini + KY-018 без дисплея

## Структура и сборка

1. **AC-1 (FR-1, FR-9):** `firmware/firmware_esp32c3_supermini/` является самостоятельным ESP-IDF-проектом, а `idf.py set-target esp32c3` и последующий clean build завершаются успешно.
2. **AC-2 (FR-1):** список исходников и зависимостей C3-проекта не содержит LCD/UI/animation/button модулей и не ссылается на исходники `firmware_esp32c6`.
3. **AC-3 (FR-9):** `sdkconfig.defaults` задаёт target `esp32c3`, USB Serial/JTAG console и отключённую default UART console; generated `sdkconfig` не добавлен в git.

## Подключение и ADC

4. **AC-4 (FR-2, FR-3):** code review подтверждает `GPIO4 -> ADC1_CH4`, `ADC_UNIT_1`, `12 bit` и `12 dB`; hardware smoke test использует `KY-018 VCC -> 3V3`, `GND -> GND`, `AO/S -> GPIO4`.
5. **AC-5 (FR-3):** опубликованный `raw` равен результату `adc_oneshot_read()` данного цикла и не проходит через проценты, gamma, EMA, offset или усреднение.
6. **AC-6 (FR-2, FR-6):** прошивка не конфигурирует `GPIO18` и `GPIO19` как прикладные GPIO; после flash/reset USB COM-порт остаётся доступным в Windows.

## Телеметрия

7. **AC-7 (FR-4, FR-5):** после запуска устройство отправляет строки, разбираемые как JSON с точным `id="lumabloom"`, целочисленными `ts` и `raw`, и завершающим `\n`.
8. **AC-8 (FR-5):** в telemetry-объекте нет обязательных дополнительных полей, а `raw` помещается в signed 32-bit integer.
9. **AC-9 (FR-4):** в 30-секундном serial capture после первой секунды медианный интервал между валидными telemetry-строками находится в диапазоне `150..300 ms`; кратковременные отклонения планировщика не считаются ошибкой.
10. **AC-10 (FR-4):** `ts` не уменьшается между последовательными сообщениями в одном запуске и после reset может начинаться заново.
11. **AC-11 (FR-3):** при последовательном освещении и затемнении KY-018 выборка `raw` показывает воспроизводимое изменение в одном направлении, достаточное для настройки `adcMin`, `adcMax` и `invert`; точные абсолютные границы не фиксируются критерием.

## Ошибки и восстановление

12. **AC-12 (FR-7):** unit/code-path проверка подтверждает, что ошибка `adc_oneshot_new_unit`, конфигурации канала или `adc_oneshot_read` логируется и не формирует telemetry-строку.
13. **AC-13 (FR-7):** после имитированной либо аппаратно воспроизведённой ошибки следующий цикл пытается повторно инициализировать sensor path, а после восстановления валидная телеметрия возобновляется без reset.
14. **AC-14 (FR-7):** при отсутствии открытого serial consumer устройство продолжает sensor cycle и после повторного открытия COM-порта снова выдаёт актуальные показания.

## Совместимость с Windows-приложением

15. **AC-15 (FR-5, FR-8):** существующие тесты `SensorMessageParserTests` и `SerialPortDiscoveryTests` проходят без изменения ожидаемого протокола.
16. **AC-16 (FR-8):** установленный `pc-app` находит C3-плату как LumaBloom через штатный auto-discovery на `115200` без изменений исходного кода приложения.
17. **AC-17 (FR-8):** с фактически настроенными `adcMin`, `adcMax` и `invert` изменение света меняет рассчитанный light percent и целевую яркость монитора; настройка сохраняется существующим механизмом приложения.
18. **AC-18 (FR-8):** прошивка не требует команды `calibrate` и не отправляет `calibrationResult` для начала обычной работы.

## Release и прошивка

19. **AC-19 (FR-10):** `python build_merged.py --dry-run --tag 1.2.3` завершается успешно, перечисляет build/merge-команды для единственного варианта и не создаёт артефакты.
20. **AC-20 (FR-10):** `python build_merged.py --tag 1.2.3` создаёт `luma_bloom_esp32c3-supermini_1.2.3_merged.bin` и одноимённый `.manifest.json` в `build/release/`.
21. **AC-21 (FR-10):** manifest имеет schema v1 и точные значения `version="1.2.3"`, `variant="esp32c3-supermini"`, `board="esp32-c3-super-mini"`, `flashMethod="esptool"`, `chip="esp32c3"`, `baudRate=460800`, `offset="0x0"`, а `fileName` совпадает с бинарником.
22. **AC-22 (FR-10):** повторный запуск для того же tag очищает только C3-артефакты этого tag и не удаляет ESP32-C6 release-файлы; `--skip-build` пересобирает merged image из валидных существующих build outputs либо завершается с ненулевым кодом при их отсутствии.
23. **AC-23 (FR-10):** merged binary успешно прошивается по `0x0` через `esptool --chip esp32c3`, после reset запускается и удовлетворяет AC-7—AC-11.
24. **AC-24 (FR-10):** `BundledFirmwareLocator` принимает C3 manifest, а `FirmwareFlashService` формирует команду с `--chip esp32c3`, manifest baud rate и offset без специальной ветки в `pc-app`.

## Документация и регрессия

25. **AC-25 (FR-11):** README и hardware/firmware docs содержат C3 wiring, build/flash/release-команды, USB Serial/JTAG ограничение и порядок настройки ADC-диапазона.
26. **AC-26 (FR-11):** документация явно отделяет общую для C6/C3 верхнюю часть цветка от C6-специфичного нижнего горшка и сообщает, что отдельный горшок и крепление платы для Super Mini пока отсутствуют.
27. **AC-27 (совместимость):** ESP32-C6 default и touch builds либо их `build_merged.py --dry-run` проверки продолжают работать, а существующие telemetry/parser tests проходят.
28. **AC-28 (нефункциональные требования):** code review runtime loop подтверждает отсутствие heap allocation, создания task/handle и накопления очереди на каждой итерации; все долгоживущие ресурсы создаются при инициализации или повторной инициализации после ошибки.
29. **AC-29 (нефункциональные требования):** protocol id и read interval имеют по одному владельцу в `app_config.h`, а publisher получает их через интерфейс либо include без дублирования literal в runtime-модулях.

## Минимальный протокол ручной проверки

1. Собрать C3-проект из чистого build-каталога.
2. Подключить KY-018 по документированной схеме и прошить merged binary.
3. Записать 30 секунд serial output на `115200`, проверить JSON, интервал и монотонность `ts`.
4. Поочерёдно закрыть датчик и осветить его, зафиксировать полезный диапазон и направление `raw`.
5. Запустить `pc-app`, убедиться в auto-discovery и изменении вычисляемой яркости после настройки диапазона.
6. Вызвать ошибку ADC управляемым test fault injection, убрать fault и проверить автоматическую повторную инициализацию и возобновление.
