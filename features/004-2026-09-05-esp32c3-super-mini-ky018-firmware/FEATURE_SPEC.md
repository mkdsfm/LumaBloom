# Спецификация: прошивка ESP32-C3 Super Mini + KY-018 без дисплея

## Краткое описание

Добавить в LumaBloom второй аппаратный трек: отдельную ESP-IDF-прошивку для платы `ESP32-C3 Super Mini` с аналоговым датчиком освещённости `KY-018`, без дисплея, кнопок и локального UI.

Устройство считывает исходное значение ADC и приблизительно каждые `200 ms` передаёт его по USB Serial в существующем JSONL-формате LumaBloom. Текущий Windows-клиент должен обнаруживать устройство и обрабатывать его телеметрию без изменения wire-протокола и кода `pc-app`.

## Проблема

В репозитории есть только полнофункциональная прошивка для Waveshare ESP32-C6 с LCD. Для компактной и дешёвой сборки без экрана отсутствует поддерживаемый firmware-проект, документированная распиновка, проверяемая процедура сборки и совместимый release-артефакт.

## Пользователи и цели

Основной пользователь — владелец Windows-компьютера, которому нужен компактный USB-датчик освещённости без дисплея.

Цели:

- поддержать `ESP32-C3 Super Mini + KY-018` как отдельный аппаратный трек;
- сохранить текущий протокол и автоматическое обнаружение в `pc-app`;
- обеспечить повторяемые build, flash и release-сценарии ESP-IDF;
- явно задокументировать подключение датчика, общие детали цветка и отсутствие отдельного нижнего горшка для ESP32-C3.

## Сценарии

### Первичная прошивка

1. Пользователь подключает KY-018 к `3V3`, `GND` и `GPIO4` платы ESP32-C3 Super Mini.
2. Собирает проект с target `esp32c3` и прошивает плату через её USB-порт.
3. После перезапуска устройство появляется в Windows как COM-порт и начинает публиковать телеметрию.

### Работа с Windows-приложением

1. `pc-app` перебирает доступные COM-порты на скорости `115200`.
2. Получает валидную строку `{"id":"lumabloom","ts":1234567,"raw":1840}`.
3. Выбирает порт и использует `raw` с текущими настройками нормализации, сглаживания и кривой яркости.

### Ошибка датчика

1. Инициализация или чтение ADC завершается ошибкой.
2. Прошивка записывает диагностическое сообщение в лог и не публикует вымышленное значение `raw`.
3. Через очередной интервал прошивка повторяет инициализацию и после восстановления автоматически возобновляет валидную телеметрию.

## Функциональные требования

### FR-1. Отдельный firmware-проект

В `firmware/firmware_esp32c3_supermini/` должен находиться самостоятельный ESP-IDF-проект с target `esp32c3`. Он не должен включать LCD-драйверы, графические assets, display task, кнопки или зависимости от прошивки ESP32-C6 во время сборки.

### FR-2. Поддерживаемая аппаратная конфигурация

Базовая распиновка:

| KY-018 | ESP32-C3 Super Mini |
| --- | --- |
| `VCC` / `+` | `3V3` |
| `GND` / `-` | `GND` |
| `AO` / `S` | `GPIO4` (`ADC1_CH4`) |

Используется только аналоговый выход. Питание датчика от `5V` не поддерживается. `GPIO18` и `GPIO19`, занятые встроенным USB Serial/JTAG, не должны переназначаться.

### FR-3. Считывание датчика

Прошивка должна использовать ESP-IDF ADC oneshot driver, `ADC_UNIT_1`, `ADC_CHANNEL_4`, разрядность `12 bit` и attenuation `12 dB`. В telemetry передаётся непосредственный целочисленный результат ADC без firmware-side нормализации, гаммы, EMA, усреднения или пересчёта в проценты.

### FR-4. Частота и время

После запуска прошивка должна пытаться получить новое показание приблизительно каждые `200 ms`. Поле `ts` содержит целое неотрицательное число миллисекунд с момента запуска устройства и не обязано сохраняться после перезапуска.

### FR-5. Wire-протокол

Каждое успешное чтение должно формировать ровно одну строку UTF-8/ASCII JSON:

```json
{"id":"lumabloom","ts":1234567,"raw":1840}
```

Строка завершается `\n`. Нормативные поля:

- `id` — строка `lumabloom`;
- `ts` — uptime в миллисекундах;
- `raw` — знаковое 32-битное целое с исходным результатом ADC.

Новые обязательные поля и сообщения состояния в wire-контракт не добавляются. Логи ESP-IDF могут находиться в том же serial-потоке: `pc-app` уже игнорирует строки, не являющиеся поддерживаемой телеметрией.

### FR-6. USB Serial

Основной транспорт — встроенный USB Serial/JTAG ESP32-C3, выведенный на USB-разъём поддерживаемой платы. Консоль ESP-IDF должна быть направлена в `CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG`; UART console и light/deep sleep не используются. Логическая скорость соединения для `pc-app` остаётся `115200 baud`.

### FR-7. Ошибки и восстановление

При ошибке инициализации или чтения ADC прошивка должна:

- записать причину через ESP-IDF logging;
- не отправлять telemetry-объект с ошибочным, предыдущим или подставным `raw`;
- пометить sensor handle как требующий повторной инициализации;
- повторить инициализацию на следующем цикле без перезапуска устройства.

Ошибка записи в serial не должна останавливать цикл чтения. После восстановления соединения или датчика публикация продолжается автоматически.

### FR-8. Совместимость с `pc-app`

Текущие `SensorMessageParser`, `SerialPortDiscovery` и обработка `raw` не меняются. ESP32-C3 использует общий встроенный baseline приложения (`adcMin=200`, `adcMax=3200`, `invert=true`) как стартовые настройки; пользователь может скорректировать диапазон и направление через UI или `appsettings.json` по фактическим показаниям своего экземпляра KY-018.

Firmware-side команда калибровки и ответы `calibrationResult` не требуются.

### FR-9. Сборка и прошивка

Проект должен собираться ESP-IDF 6.x командами:

```powershell
idf.py set-target esp32c3
idf.py build
idf.py -p COM5 flash monitor
```

`sdkconfig` остаётся локальным generated-файлом; воспроизводимые настройки target и USB console хранятся в `sdkconfig.defaults`.

### FR-10. Release-артефакт

Проект должен иметь обязательный `build_merged.py`, соответствующий контракту `firmware/README.md`. Для единственного варианта `esp32c3-supermini` скрипт создаёт:

```text
build/release/luma_bloom_esp32c3-supermini_<tag>_merged.bin
build/release/luma_bloom_esp32c3-supermini_<tag>_merged.bin.manifest.json
```

Manifest schema v1 содержит `variant="esp32c3-supermini"`, `board="esp32-c3-super-mini"`, `flashMethod="esptool"`, `chip="esp32c3"`, `baudRate=460800` и `offset="0x0"`. Артефакт должен прошиваться как full-device image и автоматически подхватываться существующими release skills и экраном `Update`.

### FR-11. Документация

Документация должна описывать новый hardware track, распиновку, требования USB, build/flash/release-команды, ожидаемую телеметрию и настройку фактического ADC-диапазона. Общая часть печатного цветка должна быть описана как одинаковая для ESP32-C6 и ESP32-C3, а существующий нижний горшок и крепление платы — как C6-специфичные. Отдельная модель горшка для ESP32-C3 пока отсутствует.

## Нефункциональные требования

- Прошивка после старта работает непрерывно и не требует пользовательского ввода.
- В steady state не создаются динамические ресурсы на каждый sensor cycle.
- Отсутствие дисплея не должно оставлять неиспользуемые UI-задачи или графические зависимости.
- Идентификатор протокола, период публикации и JSON-формат определяются в одном конфигурационном/владельческом месте, а не дублируются по модулям.
- Изменение не должно ухудшать сборку, release-артефакты или документацию ESP32-C6.

## Совместимость и миграция

- Wire-протокол остаётся без изменений; миграция `pc-app` и пользовательских настроек не требуется.
- Новый firmware-проект сосуществует с `firmware/firmware_esp32c6/`; существующий код ESP32-C6 не переносится и не удаляется.
- Portable release получает дополнительную пару `.bin` + manifest через существующее обнаружение firmware-проектов.
- Для платы с USB-UART bridge вместо выведенного встроенного USB Serial/JTAG данная конфигурация не гарантируется; такой вариант платы находится вне заявленного hardware target.

## Вне scope

- дисплей, LED-индикация, кнопки, Wi-Fi, Bluetooth, web UI и OTA;
- firmware-side нормализация, калибровка, сглаживание или управление яркостью монитора;
- изменение JSONL-протокола или `pc-app`;
- новый runtime device profile и автоматическое определение отдельных ADC-границ для C3;
- разработка нового нижнего горшка, крепления платы или иных 3D-моделей специально для ESP32-C3 Super Mini;
- поддержка цифрового выхода или иных датчиков;
- поддержка неизвестных ревизий Super Mini, чей USB-разъём не подключён к встроенному USB Serial/JTAG ESP32-C3.

## Измеримые результаты

- чистая ESP-IDF-сборка для target `esp32c3` завершается успешно;
- подключённая плата выдаёт валидную LumaBloom-телеметрию с периодом около `200 ms`;
- `pc-app` обнаруживает её без программных изменений;
- изменение освещения устойчиво изменяет `raw`, а после настройки диапазона меняет целевую яркость;
- release-скрипт формирует прошиваемый merged binary и валидный manifest.

## Допущения

- Целевая ESP32-C3 Super Mini имеет USB-разъём, подключённый к встроенному USB Serial/JTAG контроллеру ESP32-C3.
- На целевой плате выведены `3V3`, `GND` и `GPIO4`.
- KY-018 работает от `3.3V`, а его `S`/`AO` является аналоговым выходом.
- Точный полезный диапазон конкретного датчика зависит от экземпляра и условий установки, поэтому не становится новым жёстким firmware-контрактом.

- [USB Serial/JTAG Controller Console](https://docs.espressif.com/projects/esp-idf/en/latest/esp32c3/api-guides/usb-serial-jtag-console.html) — console configuration, flash и ограничения sleep/pin reuse.

Нет. Аппаратная граница, распиновка, протокол и интеграция следуют существующему ESP-IDF-треку и общему firmware-контракту репозитория.
