# Спецификация: выбор COM-порта при прошивке из UI

## Краткое описание

Добавить на экран `Update` Windows-приложения LumaBloom выпадающий список COM-портов для прошивки встроенной версии firmware.

Приложение по-прежнему автоматически обнаруживает устройство по валидной LumaBloom-телеметрии. Автоматически найденный порт является выбором по умолчанию, но пользователь может выбрать другой доступный COM-порт непосредственно перед прошивкой. Перед каждым раскрытием списка приложение заново получает список системных COM-портов.

Фича относится только к `pc-app`. Она не меняет firmware, JSONL-протокол, скорость порта, формат release-артефактов и автоматический выбор порта для чтения телеметрии.

## Проблема

Сейчас команда `Flash firmware` использует только `DashboardSnapshot.PortName`, то есть порт, на котором приложение ранее подтвердило LumaBloom-телеметрию. Пользователь не может исправить выбор при наличии нескольких устройств, выбрать плату, которая не отдала телеметрию, или указать порт после смены режима USB/переподключения.

Кроме того, запрос прошивки обрабатывается только после успешного подключения основного serial reader. Поэтому текущий UI не позволяет запустить прошивку вручную, если автообнаружение телеметрии не завершилось.

## Пользователи и цели

Основной пользователь — владелец LumaBloom, обновляющий ESP32-C6 из переносимой Windows-сборки приложения.

Цели:

- сохранить автоматический выбор корректного порта как основной бесшовный сценарий;
- дать пользователю явный выбор из актуальных COM-портов;
- позволить запустить прошивку на выбранном порту даже без успешно подключённого telemetry reader;
- явно показывать, какой порт будет передан `esptool.exe`.

## Пользовательские сценарии

### Автоматически обнаруженное устройство

1. Приложение обнаруживает LumaBloom по телеметрии на `COM8`.
2. Пользователь открывает экран `Update`.
3. В поле порта по умолчанию выбран `COM8`.
4. Пользователь нажимает `Flash firmware`.
5. Firmware прошивается на `COM8`.

### Ручной выбор при нескольких портах

1. В системе доступны `COM3`, `COM8` и `COM12`; автоматически обнаружен `COM8`.
2. Пользователь раскрывает список, после чего приложение заново перечисляет доступные порты.
3. Пользователь выбирает `COM12`.
4. При запуске прошивки `esptool.exe` получает `--port COM12`.

### Нет автоматически обнаруженной телеметрии

1. Приложение находится в состоянии `WAITING`, но Windows видит подключённый COM-порт.
2. Пользователь раскрывает список и выбирает этот порт.
3. Пользователь может запустить прошивку, не дожидаясь успешного автообнаружения LumaBloom-телеметрии.

### Состав портов изменился

1. Пользователь подключает или отключает USB-устройство после открытия экрана `Update`.
2. При следующем раскрытии список строится заново.
3. Исчезнувшие порты удаляются, новые появляются.

## Функциональные требования

### FR-1. Элемент выбора порта

На экране `Update` должен быть видимый, доступный с клавиатуры и мышью выпадающий список COM-портов рядом с информацией и действиями для firmware.

### FR-2. Источник списка

Список должен содержать текущие имена портов, возвращённые Windows через `System.IO.Ports.SerialPort.GetPortNames()`. Имена должны быть без дубликатов и отображаться в стабильном регистронезависимом порядке. Если Windows предоставляет friendly name устройства, dropdown показывает его после имени порта. Устройства с USB VID `303A` помечаются как `Espressif/ESP32`, а подтверждённый telemetry-порт — как автоматически обнаруженный LumaBloom.

Перечисление портов не должно открывать их, читать телеметрию или блокировать текущий serial reader.

### FR-3. Обновление при раскрытии

При первом входе на экран `Update` приложение должно заполнить список и показать default selection. Непосредственно перед каждым раскрытием выпадающего списка приложение должно заново перечислить системные COM-порты и заменить содержимое списка актуальным результатом. Фоновый polling портов не требуется.

### FR-4. Выбор по умолчанию

Если пользователь ещё не делал ручной выбор и текущий автоматически обнаруженный `DashboardSnapshot.PortName` присутствует среди доступных портов, он должен быть выбран по умолчанию.

Если ручной выбор уже сделан и выбранный порт всё ещё доступен при следующем раскрытии, выбор сохраняется. Если он исчез, ручной выбор сбрасывается и приложение выбирает текущий автоматически обнаруженный порт, если тот доступен; иначе остаётся состояние «порт не выбран».

При последующем автоматическом переподключении новый найденный порт становится значением по умолчанию только пока нет действующего ручного выбора.

### FR-5. Область действия ручного выбора

Ручной выбор:

- используется только как порт назначения встроенной прошивки на экране `Update`;
- действует до завершения текущего процесса приложения либо до исчезновения/изменения выбора;
- не записывается в `appsettings.json`;
- не меняет автоматическое обнаружение и выбор порта для чтения LumaBloom-телеметрии.

### FR-6. Запуск прошивки

При нажатии `Flash firmware` запрос должен зафиксировать выбранное имя порта. Обработчик и `FirmwareFlashService` должны использовать именно это зафиксированное значение, даже если состояние соединения или выбор UI изменятся после постановки запроса в очередь.

Прошивка разрешена, когда одновременно выполнены условия:

- встроенный firmware-файл доступен;
- порт выбран;
- firmware update не выполняется в данный момент.

Успешное подключение telemetry reader не является обязательным условием.

### FR-7. Проверка перед запуском

Непосредственно перед освобождением serial reader и запуском `esptool.exe` обработчик должен ещё раз убедиться, что выбранный порт присутствует в текущем системном списке. Если порт исчез, прошивка не запускается, состояние выбора обновляется, а пользователю показывается понятная ошибка.

### FR-8. Владение портом и восстановление

Если выбранный для прошивки порт совпадает с портом активного `SerialSensorReader`, reader должен быть закрыт до запуска `esptool.exe`.

Если выбран другой порт, работающий reader не требуется закрывать ради освобождения выбранного порта. Однако обычная обработка телеметрии не должна конкурировать с синхронным процессом firmware update.

После успешной или неуспешной попытки приложение не принуждает runtime-соединение использовать вручную выбранный flash-порт. Если telemetry reader отсутствует или был закрыт для прошивки, приложение возвращается к существующему автоматическому поиску LumaBloom. Если reader другого порта не закрывался, обычное чтение с него продолжается.

### FR-9. Состояния UI

- При пустом списке показывается локализованное состояние «COM-порты не найдены»; прошивка недоступна.
- При наличии портов, но отсутствии выбранного значения показывается локализованное состояние «Выберите порт»; прошивка недоступна.
- Во время `BundledFirmwareSnapshot.IsBusy=true` список и кнопка повторного запуска прошивки недоступны.
- Статус и запись в `Events` для запуска, успеха и ошибки должны содержать фактически использованный порт.
- Ошибка перечисления портов не должна завершать приложение; список переходит в состояние ошибки, прошивка остаётся недоступной до успешного обновления.

### FR-10. Локализация

Новые подписи, placeholder и сообщения должны поддерживать существующие языки `en`, `ru` и `es`. Технические имена `COM3`, `COM8` и подобные не переводятся.

## Нефункциональные требования

- Раскрытие списка не должно выполнять длительное telemetry-probing и не должно заметно замораживать Terminal.Gui UI.
- Список и кнопка должны работать с клавиатуры и мышью в существующей модели навигации.
- Обновления runtime state должны оставаться потокобезопасными.
- Один пользовательский запрос должен приводить максимум к одному запуску `esptool.exe`.
- Аргументы процесса должны передавать имя порта как отдельное безопасно экранированное значение; выбранная строка должна происходить только из системного списка портов.
- Компактный режим и поддерживаемые локализации не должны приводить к перекрытию списка, текста статуса и кнопок.

## Совместимость

- Текущий автоматический поиск LumaBloom по валидной телеметрии сохраняется.
- `connection.baudRate` и `connection.discoveryTimeoutMs` сохраняют текущую семантику.
- Новое поле конфигурации и миграция `appsettings.json` не требуются.
- Команда `esptool.exe` сохраняет `--chip`, baud прошивки `460800`, `write-flash 0x0` и выбранный bundled `.bin`.
- Portable package по-прежнему должен содержать `Tools/esptool.exe` и папку `Firmware/`.

## Вне scope

- ручной выбор порта для постоянного чтения телеметрии;
- сохранение порта между запусками приложения;
- выбор baud rate, chip, firmware-файла или flash offset;
- отображение raw VID/PID, серийного номера или расширенной USB-диагностики;
- автоматическая установка драйверов;
- изменение firmware или wire-протокола;
- подтверждение/отмена уже запущенного процесса `esptool.exe`.

## Метрики результата

- В ручной проверке пользователь может выбрать любой текущий COM-порт и увидеть его в фактической команде/статусе прошивки.
- Подключение или отключение порта отражается при следующем раскрытии без перезапуска приложения.
- Существующий сценарий прошивки автоматически обнаруженного устройства не требует дополнительного выбора.

## Допущения

- Имена, возвращаемые `SerialPort.GetPortNames()`, являются доверенным источником допустимых flash-портов.
- Ручной выбор нужен только для текущего процесса и только для прошивки.
- Идентификатором выбора остаётся имя COM-порта; friendly name и ESP32/LumaBloom markers используются только для отображения.

## Открытые вопросы

Нет. Требуемый UX выбора и частота обновления списка подтверждены пользователем.
